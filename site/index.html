One AI model, across the computers you already own.

Sangama (संगम) means confluence. It splits a language model's layers across Macs, GPUs and CPUs, so a model too large for any one device can run on several, with encrypted, invitation-only connections between them.

View the code See the test results

How it works

A language model predicts each next word-piece (a token) by passing numbers through a stack of layers. Sangama gives each computer a contiguous slice of those layers.

1

Contribute

Each worker loads only the slice of the model it serves, sized to the memory it offers: unified memory on a Mac, VRAM on a GPU.

2

Route

A client checks that its workers cover every layer in order, reserves them, and sends the prompt through the chain.

3

Generate

The last worker picks the next token and returns it. Each worker keeps its own conversation state, so only a few kilobytes move per hop.

Architecture

Sangama keeps three questions apart: who may join, how peers reach each other, and where the model runs.

Invitation-only

Single-use invitations, 24-hour membership and fast revocation. Peers pin the portal's key and drop anyone not on the signed list.

Pinned model

Workers verify every weight file by SHA-256 against a pinned manifest. A route can't silently mix models or precisions.

Two engines

Candle for exact F32 on CPU, Metal and CUDA; llama.cpp for Vulkan, ROCm and quantized GGUF weights. Both can share one route.

Honest limits

Workers can see the data they process, so today's network is for trusted groups. Signatures prove membership, not correct computation.

What the testing caught

GPU context bug

CUDA workers failed on every session after the first. Found by the relay test, reproduced locally, fixed and re-tested over five sessions in a row.

Relay time limit

Relay circuits closed after two minutes, cutting off requests in flight. Raised to an hour; four minutes of continuous traffic then ran clean.

Mixed weight files

Two differently quantized copies of the same model were silently accepted in one route. Workers now report a hash and routes refuse the mix.

Roadmap

Today's network proves the pieces with a small model. Next:

  • Large open models. Qwen3.5-397B is the first target: about 3–5 well-placed peers per copy at 4-bit.
  • Published weights. Quantize once, publish per-worker slices with their hashes, and have each worker download only the layers it serves.
  • More hardware. AMD, Intel, Qualcomm and Windows test runs, then phones.
  • Region-aware routing. Keep each route within one city or region, since round trips dominate speed.
  • Two home networks. The next acceptance test: two home routers, relay, and direct hole punching.
