# Qwen3.5-397B across three US states: relay or direct, TCP or QUIC (30 September 2026)

Round 13. The earlier three-stage fleets sat in one datacenter, so they could not show what direct connections or a different transport save across distance. This one puts real distance between the stages.

## Summary

- **Direct connections: one request 17 % faster** (8.85 to 10.4 tok/s). Network time per pass fell from 98.6 to 82.6 ms, which is what the measured distances predict.
- **QUIC: no change in steady speed**, relayed or direct. Its measurable gain here is the first token: about 0.3 s against 0.55 s over direct TCP.
- **Under load, direct is 9–12 % ahead of relayed**, and TCP and QUIC are level once connections have settled.
- Network time is now 85 % of a pass on this fleet, against 25 % when the three stages shared a datacenter.

## Setup

| | |
|---|---|
| Model | Qwen3.5-397B-A17B, Q4_K_M, 3 stages of 20 layers |
| Stages | RTX PRO 6000 (96 GB) in Maryland, Utah and Texas |
| Relay and client | One machine in Colorado |
| Settings | 48 sessions per stage, batching and the shared attention buffer on, no drafts |
| Build | Commit `c496f38` (adds QUIC) |
| Cost | About $4.80 an hour |

Round trips between machines, measured by timing a real reply (the SSH banner's TCP connect):

| | Relay (Colorado) | Maryland | Utah | Texas |
|---|---|---|---|---|
| Relay (Colorado) | – | 43 ms | 26 ms | 26 ms |
| Maryland | | – | 60 ms | 39 ms |
| Utah | | | – | 34 ms |

A pass goes client, Maryland, Utah, Texas, client. Half of each round trip per hop gives about 95 ms through the relay and about 82 ms direct. The client runs on the relay machine, so its two hops are the same either way.

## Results

Each mode restarts every mesh process with a different configuration; the loaded models are untouched. 128 tokens per request.

| Mode | One request | Network and handling per pass | First token | 16 requests, whole run | 48 requests, whole run |
|---|---|---|---|---|---|
| TCP through the relay | 8.8–8.9 tok/s | 98.6 ms | 0.40–0.45 s | 113 tok/s | 225 tok/s |
| QUIC through the relay | 8.7–8.8 | 96–97 ms | 0.33–0.46 s | 110 | 203 |
| TCP direct | 10.3–10.4 | 82.6 ms | 0.55 s | 127 | 247 |
| QUIC direct | **10.4–10.5** | **81.4 ms** | **0.28–0.31 s** | **128–129** | 243–245 |

GPU compute was 14.0–14.1 ms per pass and waiting inside workers 0.2 ms in every mode.

- **TCP direct under load was run twice.** The first run gave 78 and 184 tok/s; the repeat, after connections had settled, gave 127 and 247. The table shows the repeat. One stage still held relayed connections alongside direct ones during that mode, and requests alternate between a peer's connections, so a run can land on the slower path. Relayed connections are only closed when no call to that peer is in flight, which under steady load may be never.
- **QUIC direct was also run twice:** 128 and 245, then 129 and 243.
- **Every request completed in every mode.** Between a third and a half matched their solo tokens, as in earlier batched runs.

## What this means

- **The gain from direct connections depends on where the relay is.** Here it sat between the stages, so going direct saved 16 ms of 99. A relay far from the stages would cost more to go through.
- **QUIC does not make a healthy link faster.** These are datacenter links with little loss. Its case rests on things this fleet does not have: links that drop packets, where one lost packet stalls every session on a TCP connection, and home routers, where hole punching is the way to connect at all.
- **Distance is the speed limit again.** The same three stages in one datacenter ran one request at 48–50 tok/s; across three states they run at 9–10.

## Problems met

- **One rented machine never started** (status "loading", intended "stopped") and was replaced.
- **The relay machine cannot reach its own public address.** The client, which runs on it, could not dial the relay that way and now uses the local address.

## Limits

- Single runs, apart from the two repeated cells. No packet loss or home networks.
- No drafts in this round.

## Next

- Close a relayed connection as soon as a direct one works, even under load.
- Test with injected packet loss, and between two home networks, where QUIC and hole punching are supposed to matter.
