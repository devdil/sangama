# Relay test over the Internet, 2026-09-29

First run of the admitted mesh through a real Circuit Relay v2 server on the public Internet, using live portal membership. Scenario C8 in the [scenario matrix](scenario-matrix.md).

## Setup

| Role | Machine | Network |
|---|---|---|
| Relay | Portal server (Linode, `in-maa` region), 1 vCPU, 2 GB | Public TCP 9000, opened by the `mesh_relay` Terraform switch |
| Client | Same server, separate peer identity | Outbound only |
| Worker, shard 0 | Maintainer's Mac (Apple M5 Pro, Metal, Candle F32) | Home network |
| Worker, shard 1 | Vast.ai box in Wisconsin, US (RTX 3060, Candle CUDA F32) | Datacenter container |

- **Membership:** all four peers joined `sangama-private-v1` with single-use, 24-hour invitations from the live portal. They pinned the portal's authority key and were revoked after the test.
- **Relay only:** every non-relay node set `force_relay`, so all traffic went through the relay; there was no direct or hole-punched path.
- **Network:** TCP connect to the relay port took 238 ms from the Mac and 252 ms from the US box.
- **Route:** each token goes client → relay → Mac → relay → US → relay → client.

## Results

| Run | Result | First token | Decode |
|---|---|---|---|
| First generation | ✅ exact F32 reference tokens | 4.2 s | 1.28 tok/s |
| Second generation | ❌ `CUDA_ERROR_INVALID_CONTEXT` on the US worker (bug 1) | | |
| After bug 1 fix, 3 generations | 2 ✅ exact, 1 ❌ circuit closed mid-request (bug 2) | 1.9–2.1 s | 0.9–1.25 tok/s |
| After bug 2 fix, back-to-back for 242 s | ✅ **7/7 exact**, across two former 120 s circuit limits | median 2.5 s | median 0.64 tok/s |

This route crosses the relay three times per token, over long legs, so the speed reflects distance rather than relay overhead. The direct Mac → US route (C1) decodes at 3.1 tok/s.

## Bugs found and fixed

1. **Candle CUDA workers failed every session after the first.**
   - Cause: CUDA contexts are current per thread. Resetting a session dropped the KV-cache tensors on a runtime thread with no context bound. The failed free was recorded as `CUDA_ERROR_INVALID_CONTEXT`, and cudarc returned that error from every later call.
   - It also reproduced without the mesh: sessions 2 and 3 failed on plain local workers. Earlier NVIDIA runs missed it because the route-matrix runner starts fresh workers for every scenario.
   - Fix: `ShardedModel` binds the device's CUDA context on the current thread before `forward` and `clear`. Five sessions in a row then passed on the same workers.
2. **Relay circuits closed after 120 s, failing the request in flight.**
   - The client's circuit opened at 12:10:32.700 and closed at 12:12:32.700. The request in flight failed with "Connection was closed before a response", and a new circuit opened 3 s later.
   - A KV-cache step cannot be safely replayed, so the request is lost.
   - Fix: the relay allows circuits of one hour and 1 GiB. Reservation and per-peer circuit caps are unchanged.
3. **Linux-only clippy failure** in the cgroup memory check (`collapsible_if`). It never compiled on macOS, so it went unnoticed until the Linux build.

## Operational notes

- The local copy of the authority public key was stale; nodes must pin the key the live portal uses.
- Mesh nodes on one machine cannot share it: every node binds all of its bridge ports, so the client and each worker need separate hosts (or containers).
- The Terraform SSH allowlist is a single /32; the maintainer's ISP changes the public IPv4, so SSH access needs the allowlist updated first.
- The relay ran as a native binary beside the portal containers. A permanent relay belongs in the portal's Compose file as its own service.
